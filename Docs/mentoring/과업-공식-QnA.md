# 과업 관련 공식 Q&A (운영/심사 측 답변)

> 대규모 트래픽 선착순 쿠폰 발급 시스템 · 2조 "투게더"
> 1차·2차 멘토링에서 "다른 멘토와 논의 후 답변 예정"으로 넘어갔던 항목 중 일부가 여기서 정리됨.
> 멘토링 답변 정리는 [1차-멘토링.md](./1차-멘토링.md), [2차-멘토링.md](./2차-멘토링.md).

전반 기조: **필수 세부과업(선택사항 제외)은 모두 준수**해야 하며, **주제를 벗어나지 않는 선에서**
추가 기능/서비스 구현이나 더 어려운 조건에서의 검증에 성공하면 **강점**이 된다.
평가는 "세부과업 수행 여부 + 전체적인 밸런스 + 완성도"로 이뤄지며, 정확한 평가 기준은 안내되지 않는다.

## 1. 프로젝트 범위

| 질문 | 답변 |
| --- | --- |
| 커머스 서비스 전체(주문·배송 등)를 만들어야 하는지, 선착순 쿠폰 발급/검증만 하면 되는지 | **선착순 쿠폰 관련 기능만** 진행 |
| 로그인·알림 등 생략되는 게 많은데, 세부 과업에 나온 기능만 완성해도 되는지 / 완전한 서비스 형태여야 하는지 | 로그인은 구현하지 않되, **가상 회원 ID 또는 마스킹 가능한 식별값**을 사용해 발급 주체를 식별한다 |
| 기능 구현에 집중할지, 서비스 구현에도 초점을 맞출지 | 세부과업의 **필수사항(선택사항 제외)은 모두** 지킬 것. 주제를 벗어나지 않는 선에서 **추가 기능/서비스 구현에 성공하면 강점** |

## 2. 전체 전제 조건

### 2-1. "알림 발송 등 외부 연동은 Mocking 처리" 의 의미

- 외부 연동이 필요한 기능은 **실제로 구현하지 말고, API가 있다는 가정 하에 Mocking 처리**.
- 단순 로그 출력이냐 Mock 서버 구축이냐 → **Mock 서버를 따로 구축할 필요 없음.**
- 예: 쿠폰 발급 시 알림 발송 기능을 넣는다면, 알림 발송을 실제 구현하는 게 아니라 **발송 완료 여부 등만 체크**하는 수준의 Mocking.

### 2-2. 정상 조건에서 초과 발급 0건이면 충분한지, 예외 상황까지 보는지

- 정상 조건만이 아니라 **다양한 예외 케이스 고려 및 방어 로직 구현 시 강점**이 된다.
- (예: 사용 후 취소 같은 상태 전이, Redis/서버 장애 중 발급 요청 등)

### 2-3. 더미 데이터 300만 건 vs 검증 300만 건이 같은 데이터인지

- **동일한 데이터**를 의미한다. (더미로 적재한 300만 건 = 검증 대상 300만 건)

## 3. 쿠폰 발급 시스템

### 3-1. "[쿠폰 발급 시스템]의 시작 가이드 제공"의 의미

- 기능에 대한 **가이드 제공은 가능하나, 평가 대상은 아니다.**

### 3-2. [쿠폰 발급 시스템]·[쿠폰 정합성 검증]의 선택사항을 진행하면 가산점이 있는지

- 말 그대로 **선택사항.** 잘 구현해냈는지 여부에 따라 **가산점 또는 감점**이 될 수 있다.

### 3-3. "20,000명이 동시에 요청"의 측정 기준

**모든 조가 동일한 조건으로 설정 후 측정**해야 하며, 조건은:

- **테스트 유저: 20,000명 (중복 유저 없음)**
- **ramp-up: 60s**

(→ "20,000 세션 동시 유지"냐 "짧은 구간 20,000건 도달"이냐 "ramp-up 허용"이냐 논쟁은,
위 두 수치로 통일. ramp-up 60초가 공식 조건.)

## 4. 서비스 실행 / 평가

### 4-1. 부하 테스트 실행 주체

- 우리가 실행한 결과를 시연·제출하는 것에 더해, **심사 과정에서 심사위원이 직접 실행해 볼 수 있다.**

### 4-2. 동시성 제어의 정확성을 어떻게 확인하는지 (시연/직접 실행/코드)

- 평가 기준을 정확히 안내하기는 어려움. **세부과업 수행 여부 + 전체적인 밸런스 + 완성도**를 평가.
- 심사위원에게 **구글 드라이브(깃허브, 소스코드, 시연 영상 등)를 사전 공유**하는 점 참고.

---

## 5. 평가 기준 (가산점 등)

### 5-1. 기본 조건을 다 충족한 상태에서 "백엔드를 잘 이해한다"고 느끼게 하는 차별화 요소

- 평가 기준을 정확히 안내하기는 어려움. **세부과업 수행 여부 + 전체적인 밸런스 + 완성도**를 평가.

### 5-2. 명세 최소 조건 외 더 어려운 조건에서 검증하면 긍정적으로 반영되는지

- **필수 세부과업은 반드시 준수**하고, **주제를 벗어나지 않는 선에서 검증에 성공하면 강점**이 된다.
